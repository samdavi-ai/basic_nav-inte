# Integration and command ownership

**DO NOT INTEGRATE.** The accepted standalone mission remains the control. The optional private guard reads /cmd_vel_nav and is the only intended navigation publisher to /cmd_vel_guarded_nav. In a candidate overlay the mux subscribes to the guarded topic. The downstream chain is /cmd_vel_mux → velocity_smoother → /cmd_vel_smoothed → collision_monitor → /cmd_vel_safe → terrain monitor → /cmd_vel → Gazebo. The controller and behavior server share the upstream navigation topic. Teleop and optional RL enter the mux separately. A guard on the navigation input cannot certify these other sources.

GenerationGuard runs in one ROS executor. It counts accepted local and global grid updates, rejects reversed stamps, invalidates cached approval on input changes, checks observation ages, and validates the current global path, local rollout and braking sweep on the drive tick. RotationShim may ask for a stationary alignment before DWB publishes a translating rollout. The guard checks braking, corner sweep and measured forward velocity in that branch. The safety gate defaults to a zero command. A newer costmap header alone does not establish that an obstacle has been marked.

The recovery sequence holds motion on detection, checks measured rest, waits for post-stop observations, reassesses, replans, validates the resulting rollout and then resumes. On expiry the coordinator ends the mission. One private variant uses the accepted NavFn recovery behavior and a second selects NavFn on a copied, clearance-constrained map. The live costmap and its obstacle layers retain their marks. The optional planner fence observes the planner action and requires observations following the plan stamp. Its ROS status and observation callbacks cannot provide an atomic cross-process interlock at a physics step.

In the private coordinator E-stop cancels pending replacement and finalizes the active mission under its original identifiers while the authoritative supervisor remains latched. In the observed windows, the supervisor rejected the second mission and no subsequent recovery command moved the chassis beyond the stopping limits. The eight probe recordings and their post-reset observation windows are listed in ESTOP_INTERRUPTION_MATRIX.md. The private planner-phase probe is distinct from a stop inside an instrumented planner call.

Packaging still needs a production lifecycle owner, readiness tied to actual controller configuration, startup/restart arbitration and a single guarded mux input. The existing private preflight checks plugin registration; runtime configuration and mission readiness are checked separately. Trials use private DDS domains, kernel endpoints and Gazebo partitions. They cannot qualify the normal launcher. Simulator teardown escalation is visible in launch.log and results.json. A launcher exit code alone does not prove clean shutdown or a continuous zero-command window.

A live endpoint snapshot of the control graph shows controller_server and behavior_server publishing to the mux navigation input, velocity_smoother consuming the mux output, collision_monitor producing /cmd_vel_safe, and gracemo_terrain_monitor as the sole publisher on /cmd_vel. The sensor bridge consumes that final command for Gazebo. The restart experiment recorded exact zero on the three monitored topics and mux source NONE after both individual restarts. The moving smoke failure after restart is a separate readiness defect.
