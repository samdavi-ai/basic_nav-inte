# Kernel action authorization

The operator provisions a private grant file through `VIRA_ADAPTER_GRANTS`. Each entry has a unique id, a bearer token at least 32 characters long, and approved action names. Use independent, randomly generated tokens. The SDK consumes a process-specific `VIRA_ADAPTER_TOKEN` or a private, user-owned `VIRA_ADAPTER_TOKEN_FILE`. The voice process can receive its own path from the launcher through `VIRA_VOICE_TOKEN_FILE`. An unprovisioned client cannot request actions. Never put tokens in arguments, source control, receipts or evidence.

The client connects to acquire or renew a 30-second lease. A reconnection after disconnect or expiry changes the session identity. The kernel parses the typed action, checks identity, capability, trace, current navigation state and pending recovery review. It stores the exact request in memory and issues a five-second, one-use opaque handle. The receipt includes the SHA-256 of the kernel-serialized parameters, issuer, policy version, session, action, mission and trace identifiers. Verification requires the kernel-held request and the original authenticated principal. A copied JSON receipt is insufficient to dispatch. The SDK follows no redirects and restricts plaintext credentials to loopback. An interruption invalidates outstanding movement handles. SQLite records the dispatch decision and action atomically before publication and enforces unique action and new-mission IDs. A crash between persistence and broadcast leaves execution uncertain.

Generic HTTP and Unix event ingestion reject typed action requests. Voice actions no longer notify local ROS listeners prior to authorization. The ROS bridge executes actions received on the kernel event stream. Operator grants, SQLite, the same-user operating environment, the kernel process, the ROS domain and the telemetry producers remain trusted. Direct DDS publishers are outside this authorization boundary. An unauthenticated telemetry feed is insufficient to establish trustworthy safety state in an adversarial deployment. Authorization remains PARTIALLY IMPLEMENTED.

The boundary observer subscribed to /coordinator/command, submitted an uncredentialed mission, and observed the same topic throughout an authorized mission. Each boundary.json contains the denied identity, HTTP status, observed commands and positive-control correlation. This evidence covers the sampled ingress and observation window. Component tests additionally cover missing connection, adapter mismatch, capability mismatch, immutable dispatch fields, disconnect/reconnect, expiry and duplicate consumption. A live grant change invalidated the outstanding handle and revoked the old capability in the isolated kernel test. Durable records for malformed or anonymous requests, all requested audit query filters, per-adapter process isolation, and enforcement across all distributed transports remain open.
